## 削除した条件 (破綻解・実機不可解)

| 条件 | 理由 |
|---|---|
| ddq=0.5π, ddq=1π | ddq cap 大違反 (実測 5.96 / 8.67 vs cap 1.57 / 3.14), 実行不能 |
| EE0.20/0.10 @ y0.30, EE0.20/0.10 @ xy0.20 | 狭い作業域で収束失敗, dq/EE/作業域を大違反した暴走解 |
| EE0.25 (dq 制限なし) | dq 9.43 rad/s = ハード限界 3.14 の 3 倍, 実機投入不可 |

## 主要な結論

1. **EE 速度制約だけでは関節速度を縛れない**. EE 0.25 m/s でも特異点近傍で wrist が 7.65/9.43 rad/s に
   暴走する. dq 制限の併用が必須.
2. **ddq は 2π 以上が必須**. 2π 未満に絞ると"滑らかさ"と"励起の十分さ"が両立せず最適化が破綻.
   締めても condition number は改善しない (逆効果).
3. **EE 速度は下げるほど condition number が悪化** (0.25→0.10 で 1.87→2.29). 手先を遅くすると励起の質が落ちる.
4. **作業領域を狭めるほど condition number 悪化 + feasibility 破綻**. x0.25/y0.35 では 4/4 収束, y0.30・
   xy0.20 では 2/4 が破綻. 励起には十分な作業空間が必要.
5. 低 cond の非実行可能解 (例 cond 1.62) を"良い結果"と誤認しないこと. 中身は全制約を激しく違反した暴走軌道.

## 実機投入候補

**EE≤0.25 + dq≤π/2 + ddq≤2π** (`results/best_ddq2pi/`, cond 1.83, 姿勢変化 152°, 関節速度 ≤1.57 rad/s,
加速度 ≤6.3 rad/s²). 作業領域は x0.3/y0.35 が同定品質・feasibility ともに最良.

> 注: 現在の `assets/ur5e/mjcf/ur5e_with_box.xml` の作業領域 geom は最後の実験値 **x/y 半幅 0.2** のまま.
> 実機運用時は上記の推奨 (x0.3/y0.35 = `size="0.3 0.35 0.225"`) に戻すこと.
